BA-1 + BA-2 · 底层基础
BA-1 · BA-2 · Voltage & Common Ground

电压是差值，共地是前提

所有电路的底层核心：电压是相对 GND 的差值，多模块必须共地才能通信。

BA-1：电压核心定义

电压 = 两点之间的电位差，单位伏特(V)
电压是电流产生的前提，必须形成完整回路才有电流
0V 是人为定义的参考电位（GND/地线）
电压数值默认是对 GND 的差值；负电压 = 低于 GND

关键认知

在两个未连接的独立系统中，无法得出另一个系统相对于当前系统的电位信息。这就是为什么需要共地。

BA-2：不共地的后果

❌ A 模块认为的 2V，B 模块识别不到
❌ 信号处于悬空（开路）状态
❌ 通信失败、舵机乱动等异常
新手阶段极其容易忽略这个问题！

共地规则

所有设备的 GND（地线/0V参考电位点）连接在一起，共享同一个参考电位。

// 正确接线
模块A GND ───┐
模块B GND ───┼── 共地
单片机 GND ─┘

BA-4-1 · GPIO Input

GPIO：先读到 0 和 1

单片机最基础的外设，读取引脚电平状态，高电平=1，低电平=0。

输入模式核心功能

读取引脚电平状态
⚡ 高电平 = 逻辑 1（工作电压 3.3V/5V）
🟫 低电平 = 逻辑 0（GND/0V）
🔘 最典型应用：按键检测

致命问题：悬空

按键释放时引脚无固定电平接入，处于悬空开路状态，读取值随机（可能是 0 也可能是 1）！

解决方案：上拉/下拉电阻

上拉电阻：引脚默认拉至高电平 1，按键按下时拉低为 0
下拉电阻：引脚默认拉至低电平 0，按键按下时拉高为 1
// 两种接入方式
方式一：外部接 1kΩ~100kΩ 电阻
        （常用 4.7kΩ / 10kΩ）
方式二：芯片内部上拉/下拉
        代码直接开启即可

BA-4-2 · 基础输出
BA-4-2 · GPIO Output

GPIO：再输出 0 和 1

芯片内部通过开关控制引脚连接到 VCC 或 GND，直接驱动外部元件。

推挽输出（Push-Pull）

内部两个开关，分别控制引脚接 VCC 或 GND
✅ 可直接输出高电平 1 / 低电平 0
✅ 具备一定驱动能力（单引脚最大 ~10mA）
💡 典型应用：LED 亮灭控制
// 推挽输出控制 LED
接 VCC → LED 正极=VCC, 负极=GND → 亮
接 GND → LED 正负极均=GND → 灭

开漏输出（Open-Drain）

仅一个开关控制引脚接 GND
⚠️ 无法主动输出高电平，需外接/内部上拉电阻
开关断开 → 上拉至高电平 1（但驱动能力极弱）
开关闭合 → 输出低电平 0

为什么用开漏输出？

实现「线与」逻辑：多设备输出引脚直接并接在同一总线，任一设备拉低即为低电平，所有设备释放才由上拉电阻置高，无输出短路风险。多用于通信总线场景。

核心局限：引脚只能输出纯 0 或纯 1，怎么表示 0.666 这样的中间值？→ 由此开启 PWM
只能 0 或 1 → 下一步：怎么模拟 0.666？
BA-5 · 模拟输出
BA-5 · Pulse Width Modulation

PWM：不只是 0 和 1，还有 0.666

用数字信号（只有 0/1）模拟出模拟信号（0~1），通过快速切换高低电平实现。

PWM 核心原理

通过快速切换 0/1 高低电平，用高电平在一个周期内的时间占比，模拟出连续的模拟电压。

高 ┌──┐ ┌──┐ ┌──┐
           │ │ │ │ │ │  ← 66% 占空比
低    └──┘──└──┘──└──┘
        └─周期─┘

频率

1秒内完整周期的次数。越高越平稳

蜂鸣器音调

占空比

高电平时间 ÷ 总周期时间。越大越接近高电平

LED亮度 电机转速 舵机角度

BA-6 · 硬件实现
BA-6 · Timer/Counter

0.666，用 TIM 产生

单片机内部独立硬件外设，配置完成后自主运行，不占用 CPU 资源。

外设（Peripheral）概念

单片机内部独立的硬件单元，配置完成后可自主完成特定功能，无需占用 CPU 主程序资源。GPIO、TIM、ADC 全部属于外设。

类比：外设像现实中的工具，机械计数器通过电路实现就是 TIM 定时器/计数器

TIM 三大核心参数

PSC（预分频值）：输入 PSC 个脉冲再输出 1 个脉冲，降低频率到 1/PSC
ARR（自动重装值）：计数器达到此值后清零并溢出
CCR（比较值）：决定 PWM 高电平的切换点

PWM 计算公式

PWM频率 = 主频 ÷ [(PSC+1) × (ARR+1)]
PWM占空比 = CCR ÷ (ARR+1) × 100%

信号流程

时钟频率 → 分频器(PSC) → 计数器(TIM) → IO输出

// PSC 变小 → 输出频率变大
// PSC 变大 → 输出频率变小
拓展能力：TIM 还能实现精准定时、外部事件计数 → 在中断章节中被充分使用

BA-7 · Analog-to-Digital Converter

ADC：读取 0.666，转换为 0 和 1

与 PWM/BA-5-6 形成镜像闭环，将连续模拟电压转换为离散数字信号。

ADC 核心定义

模数转换器，将连续的模拟电压信号转换为离散数字信号的单片机外设。

// 示例：5V 单片机，读取 3.1V 电压
12bit 精度: 2539/4095 → 0111 1111 0111
8bit  精度: 158/255   → 1001 1110

量程

默认以 VCC 为最大参考电压，部分单片机可通过 ADC_VREF 引脚指定

精度/分辨率

N bit = 2ⁿ 个电压台阶。常见 8bit、12bit，位数越高分辨越强

⚠️ 新手高频坑：通道切换

多路 ADC 多为异步采样（一次只获取一个通道）
切换通道后需等待一定时间（如 20μs）再采集
否则通道间相互干扰，采样结果不准确

采样率/转换时间

ADC 内部一般通过逐次逼近方式得到结果，需要一定时间完成一次转换。

铺垫：ADC 采样数据搬运 → 在 DMA 章节中做效率优化

BA-8 · Interrupt Request

IRQ：中断一下，请求先看这个！

主程序正常运行时，有紧急事件需要立刻处理，不用一直循环等待查询。

中断核心机制

通过预设触发条件暂停主程序，优先执行中断处理函数，执行完成后返回主程序断点处继续运行。

// 中断执行流程
主程序 运行中... → 触发中断!
  ↓
中断处理函数 执行 → 完成
  ↓
主程序 从断点继续运行

常见触发条件

高电平触发 低电平触发 上升沿触发 下降沿触发

常见中断来源

BA-9 · 高速通信
BA-9 · I2C / SPI Bus

I2C/SPI：少量线，多数据

用少量信号线，按约定规则实现大量数据的双向传输（串行同步通信）。

I2C 总线

仅需 2 根通信线：SCL（时钟）+ SDA（数据）
均为开漏输出（对应 BA-4-2 知识点）
支持一主机多从机
// I2C 接线
主机 ──SCL─── 从机1（OLED）
       └─SDA─── 从机2（MPU6050）
       └─VCC/GND─ 共地供电

典型应用：OLED 显示屏、LCD 屏幕、MPU6050 姿态传感器

SPI 总线

4 根信号线（单向通信可简化为 3 根）
通信速率远高于 I2C
SCK时钟信号（主机发生）
MOSI主机发→从机收
MISO主机收←从机发
CS片选信号（主机发生）
新手痛点：I2C/SPI 配置太复杂、线还是多 → 有没有更简单的方式？→ 由此开启 UART

BA-10 · 极简通信
BA-10 · Universal Async Receiver/Transmitter

UART：还是太好用了

无需时钟线，TX/RX 交叉接线，约定好参数即可双向通信，新手最友好。

UART 核心特点

✅ 异步通信，无需时钟线
✅ 仅需 TX（发送）+ RX（接收）交叉接线
✅ 双方约定好参数（波特率等）即可通信
✅ 使用门槛极低，新手最常用的调试工具
// UART 接线
设备A TX ───→ 设备B RX
设备A RX ←─── 设备B TX
设备A GND ──── 设备B GND // 别忘了共地!

典型应用

单片机 ↔ 单片机 单片机 ↔ 电脑 单片机 ↔ 蓝牙模块

电脑 USB 不能直接对接 UART

需要 TTL 转 USB 模块实现协议与电平转换：

TTL: 0V→逻辑0, 3.3V/5V→逻辑1
USB: D+/D- 电压差(±3.3V)→0和1

// 转换流程
USB ──→ TTL转USB模块 ──→ UART
       协议转换 + 电平转换

程序下载调试

常用 SWD（2线）、JTAG（4~5线）协议，通过调试模块实现电脑与单片机的程序传输与在线调试

BA-11 · Watchdog & DMA

WDG 与 DMA：锦上添花

已实现所有基础功能，最后两件事：让系统更可靠、更高效。

🐕 WDG 看门狗 — 提升可靠性

本质是独立的递减计数器
程序需定期「喂狗」重置计数器
💀 若程序卡死/跑飞未喂狗 → 计数器归零 → 自动复位重启
🛡️ 使用独立电路与独立内置时钟，即使主时钟/核心电路故障仍可工作
// 看门狗工作流程
主程序 正常运行 → 定期 喂狗() → 计数器重置
主程序 卡死/跑飞 → 未喂狗 → 计数器减到0
  ↓
💥 触发单片机复位 → 系统恢复

⚡ DMA 直接存储器访问 — 提升效率

无需 CPU 参与，自主完成数据搬运
外设 ↔ RAM、RAM ↔ RAM 之间
✅ 全程不占用 CPU 资源，也无需中断处理

典型应用

📥 UART 接收数据 → 实时搬运到 char 数组
ADC 采样结果 → 实时更新到 int 变量
💡 主程序直接读取变量 = 对应外设实时数据

冯·诺依曼 vs 哈佛架构

单片机的"大脑"怎么组织？两种经典架构决定了数据怎么流动。

冯·诺依曼架构（Von Neumann）

程序和数据共用一条总线和同一块存储器。

CPU 核心
↕
统一存储器（程序+数据）
✅ 结构简单，成本低
❌ 冯·诺依曼瓶颈：取指和取数据不能同时进行
代表：早期 x86 PC、部分 51 单片机

哈佛架构（Harvard）

程序和数据分开存储，各自有独立总线。

CPU 核心
↕
Flash
程序存储
↕
RAM
数据存储
✅ 取指和取数据同时进行，速度更快
✅ 现代 MCU 主流选择
代表：STM32、ESP32、AVR、大多数 DSP
改进型哈佛架构：现代 ARM Cortex-M 采用，总线分开但统一编址，兼顾速度与灵活性。
架构决定性能上限 → 下一步看存储器

Flash 存程序、RAM 跑变量、EEPROM 存配置、寄存器控制一切 — 各司其职。

Flash
程序存储器
🔹 断电不丢失（非易失性）

🔹 写入寿命：~10 万次

⚡

🔹 断电即丢失（易失性）

易失高速读写

🔹 断电不丢失，可字节级读写
🔹 存放校准参数、配置信息

单片机的"心跳"：时钟系统

所有数字电路按节拍工作。时钟就是节拍器，频率越高跑得越快，也越费电。

🕐 时钟来源

来源类型典型频率精度
HSI内部 RC 振荡器8/16/48 MHz±1%~5%
HSE外部晶振4~26 MHz±20ppm
LSE外部 32.768kHz32.768 kHz±20ppm
LSI内部低频 RC32~40 kHz±10%

⚡ PLL 倍频器

输入 8MHz → PLL 倍频 ×9 → 输出 72MHz。用低频晶振得到高频时钟，兼顾精度与速度。

f_out = f_in × N / (M × P)

🌳 时钟树（Clock Tree）

时钟从源头出发，经过分频/倍频，分配给各外设。

/* STM32 时钟树简化 */

HSE 8MHz ──┐
            ├→ PLL(×9) → SYSCLK 72MHz
HSI 8MHz ──┘           │
                         ├→ AHB /1 → HCLK 72MHz
                         │   ├→ APB1 /2 → 36MHz
                         │   └→ APB2 /1 → 72MHz
                         └→ ADC /6 → 12MHz

// 每个外设独立使能时钟
RCC_APB2.GPIOAEN = 1; // 开 GPIOA 时钟
省电技巧：不用的外设关掉时钟，可大幅降低功耗。这是低功耗设计的核心手段之一。

RTOS · Real-Time Operating System

RTOS：实时操作系统

当你的项目需要同时做多件事 — 采集数据 + WiFi 通信 + 屏幕刷新 — RTOS 登场。

为什么需要 RTOS？

裸机程序：一个超级大 loop()，所有任务轮流执行，互相阻塞
⚡ RTOS 程序：每个任务独立线程，按优先级调度，互不阻塞
🛡️ 实时性：高优先级任务能在确定时间内获得 CPU
📦 IPC 机制：信号量/队列/互斥锁，任务间安全通信

RTOS 核心概念

任务（Task） — 独立的执行线程
调度器（Scheduler） — 按优先级切换任务
信号量（Semaphore） — 资源计数
队列（Queue） — 任务间数据传递
互斥锁（Mutex） — 保护共享资源
定时器（Timer） — 周期性任务

📦 主流 RTOS 对比

RTOS来源特点
FreeRTOS开源(AWS)最流行、最小巧
RT-Thread国产开源中文生态好、组件全
ZephyrLinux Found.超可配置、安全
uC/OS-III商业认证级、工业
NuttXApachePOSIX 兼容
AliOS阿里IoT 云集成
选择建议：
入门 → FreeRTOS（文档最全）
国产项目 → RT-Thread（中文好）
ESP32 → 自带 FreeRTOS
功能机 → 不需要 RTOS，裸机 loop 足够

🛠️ 低功耗设计五层策略

1️⃣ 硬件层：选对芯片 + 合理供电

选 STM32L/U 系列、MSP430 等低功耗 MCU · 用 LDO 或 Buck 供电 · 不用的外设物理断开

2️⃣ 时钟层：降频 + 按需开关

空闲时降低主频 · 不用的外设关时钟 · 用 LSE 代替 HSE 维持 RTC

3️⃣ 休眠层：善用低功耗模式

Sleep（短空闲）→ Stop（长空闲）→ Standby（深度休眠）· 用 RTC 定时唤醒

4️⃣ 外设层：GPIO 状态管理

进休眠前配置所有 GPIO 为模拟输入或输出低 · 浮空引脚会漏电

5️⃣ 软件层：事件驱动代替轮询

用中断唤醒代替 while(1) 轮询 · 快速处理完事件立即重新休眠

💡 关键公式：
平均电流 = (活跃电流 × 活跃时间 + 休眠电流 × 休眠时间) / 总周期

如果 99% 时间休眠（2μA），1% 活跃（20mA）：
均值 ≈ 200μA → 一节 CR2032 约用 100 天
