03 · 硬件搭建
Hardware Assembly

花 30 分钟，搭好你的机器人

硬件组装并不复杂 — 按照文档一步步来，半小时让设备「活」起来。

购买清单

核心板ESP32-S3 开发板20-40 元

功放MAX98357A 模块8-15 元
喇叭3W 4Ω 小喇叭3-5 元
显示屏SSD1306 OLED8-12 元
其他杜邦线、面包板5-10 元

接线要点

# INMP441 麦克风 → ESP32-S3
SCK → GPIO 4
SD → GPIO 5
L/R → GND (左声道)
VDD → 3.3V

# MAX98357A 功放 → ESP32-S3
BCLK → GPIO 6
LRCLK → GPIO 7
DIN → GPIO 15
VIN → 5V

# SSD1306 OLED → ESP32-S3
SDA → GPIO 41
SCL → GPIO 42

接线完成后：先别急着通电！用万用表测一下 VCC-GND 是否短路。确认无误后上电，OLED 屏幕应显示开机画面。如果屏幕不亮，检查 I2C 接线是否接触良好。

04 · 开发环境
ESP-IDF Setup

搭建 ESP-IDF 开发环境

ESP-IDF 是乐鑫官方的开发框架 — 编译、烧录、调试一站式搞定。

环境安装步骤

1 安装 ESP-IDF — 从 GitHub 克隆 v5.4.0+ 版本
2 运行安装脚本 — install.bat (Win) / install.sh (Mac/Linux)
3 激活环境 — export.bat / . ./export.sh
4 克隆小智固件 — GitHub 仓库获取源码
5 配置项目 — idf.py set-target esp32s3
6 编译验证 — idf.py build 确认无报错
PowerShell — ESP-IDF 环境

新手提示：如果觉得命令行太复杂，可以使用 Visual Studio Code + ESP-IDF 插件，GUI 界面配置和编译，降低入门门槛。

开发环境是通往嵌入式 AI 的第一道门
05 · 固件烧录
Firmware Flashing

烧录固件 & 网络配置

把写好的代码「装」进芯片，再连上 Wi-Fi，让机器人接入互联网。

两种烧录方式

📥

预编译固件

从 GitHub Releases 下载 .bin 文件，用 ESP Flash Tool 直接烧录。无需编译环境，5 分钟搞定。

源码编译

克隆源码，idf.py build flash monitor 一键编译+烧录。适合开发自定义功能。

Wi-Fi 配网流程

1 上电后 OLED 显示 「未连接 Wi-Fi」
2 手机搜索热点 「XiaoZhi-AP-xxxx」 并连接
3 浏览器访问 192.168.4.1 进入配置页
4 输入家中 Wi-Fi 名称和密码，保存
5 机器人自动重启，OLED 显示 IP 地址即为成功
Terminal — Flash Firmware

注意：烧录前确认 USB 数据线支持数据传输（不是仅充电线）。如果烧录失败，检查 COM 端口号是否正确，并确认开发板处于下载模式。

06 · AI 能力集成
AI Capabilities

AI 三板斧：唤醒 + 对话 + 控制

小智的核心 AI 能力由三部分组成 — 本地唤醒词检测、云端大模型对话、IoT 设备智能控制。

流程：一次完整的 AI 对话

1 唤醒 — 你说"你好小智"，本地唤醒引擎检测到关键词，<200ms 唤醒
2 收音 — 麦克风开始录音，16kHz PCM 采样，Opus 压缩编码
3 ASR — 云端语音识别服务将音频转文字，<1s 延迟
4 LLM — 文字发送到 DeepSeek / GPT / Qwen 等大模型，<3s 返回回复
5 TTS — 大模型回复文字通过语音合成引擎转为自然语音
6 播报 — 功放驱动喇叭播放合成语音，同时 OLED 显示表情

支持的大模型

DeepSeek-V3 GPT-4o 文心一言 Qwen-Max ChatGLM

IoT 控制能力

# 语音指令示例
"打开客厅灯" → MQTT → 智能开关
"空调调到26度" → MCP → 空调控制
"现在室温多少" → 传感器 → 语音播报
"晚安模式" → 联动：关灯 + 关窗帘

# 架构：本地唤醒 + 云端推理
用户语音 → 本地唤醒引擎

# 延迟：控制指令 <100ms

端侧推理：ESP32-S3 支持 TensorFlow Lite 轻量模型，可实现本地关键词检测、简单手势识别等任务，无需联网。

07 · 通信协议
Communication Protocols

三大协议：WebSocket + MQTT + MCP

理解 ESP32-S3 如何与云端 AI 服务和本地设备「对话」。

协议分工

协议用途方向特点
WebSocket AI 对话通道 双向 设备 ↔ 云端大模型，实时双向音频流
MQTT 物联网控制 双向 订阅/发布模式，低带宽，适合 IoT
MCP 设备语义层 双向 Model Context Protocol，AI 理解设备
UDP 音频包传输 单向 低延迟音频流，与 MQTT 混合使用

08 · 调试与扩展
Debug & Extend

遇到问题？让 AI 帮你排查

嵌入式开发难免踩坑 — 好消息是，AI 辅助调试在这里同样高效。

常见问题 & AI 排查思路

1 烧录失败 — 把 idf.py flash 的报错日志发给 AI，检查 COM 口和下载模式
2 唤醒无反应 — 检查麦克风接线 + I2S 驱动配置，用示波器看波形
3 Wi-Fi 连不上 — 检查 SSID 是否包含特殊字符，尝试 2.4G 频段
4 语音识别不准 — 检查环境噪音，调整麦克风增益配置
5 大模型无回复 — 检查 API Key 配置 + 网络连通性

进阶：自定义功能扩展

1 自定义唤醒词 — 修改本地唤醒引擎配置，训练你的专属关键词
2 接入传感器 — 温湿度 / 光照 / 人体红外，语音查询传感器数据
3 4G 通信 — 加装 4G Cat.1 模块，野外无 Wi-Fi 也能用
4 本地推理 — 部署 TensorFlow Lite 模型，离线关键词检测
Serial Monitor — Debug Output

调试利器：串口监视器是嵌入式开发的眼睛。idf.py monitor 可以实时查看 ESP32 的运行日志，配合 AI 分析，快速定位问题根源。
