01 · 什么是 Git
What is Git

Git 是什么？

Git 是一个 分布式版本控制系统，它能记录文件的每一次修改，让你随时回到任何一个历史状态。

🎮

一句话比喻：游戏存档

每次 commit = 存一个档。随时读档、随时分叉、随时合并，再不怕改崩。

⏰

核心能力：时间机器

记录谁、在何时、改了什么、为什么改 —— 完整的项目基因图谱。

05 · 分支管理
Branch Management

分支管理 — Git 的灵魂

分支让多人并行开发成为可能。Git 的分支极其轻量，创建/切换几乎是瞬时的。

🌿 创建分支

# 创建并切换到新分支
$ git checkout -b feature/login

🔀 合并分支

# 切回 main 并合并
$ git checkout main
$ git merge feature/login

🗑️ 删除分支

# 合并后删除
$ git branch -d feature/login
分支 = 平行宇宙

07 · 高级用法
Advanced · 高级玩法

高级一：Rebase 变基

把分支的起点「移植」到最新提交上，让分叉的历史变成一条直线，干净利落。

Before · 分叉 → After · 变基后直线

🔀 它做了什么

找到两条分支的共同祖先 B，把 feature 上 B 之后的每个 commit 逐一重放到 main 末尾，生成全新的 commit（X'→X', Y'→Y'）。原 commit 的副本，hash 变了，内容不变。

⚠ 关键注意

rebase 会改写历史（生成新 hash）。已推送到公共分支的提交不要 rebase，否则队友会冲突。黄金法则：只在自己的本地分支 rebase。

# 在 feature 分支上执行
$ git rebase main   # feature 接到 main 末尾，历史变直线
rebase = 重放 commit，历史变干净
08 · 高级用法
Advanced · 交互演示

高级二：Cherry-pick 精准搬运

点「下一步」一步步看 Git 到底是怎么把一个 commit 搬过来的 —— 它复制的不是 commit 本身，而是「这次提交引入的改动」。

Step 0 · 初始状态

两个分支，各走各的

main 在 C（HEAD），feature 上有个 commit X。你只想要 X 这一个改动，不想合并整个 feature 分支。

# 在 main 分支上，准备摘取 feature 的 commit X
$ git checkout main
0 / 4
💡

核心真相：cherry-pick 复制的不是 commit 对象，而是「X 相对其父 B 的 diff」。把这个 diff 应用到当前 HEAD(C) 上，生成一个全新的 commit X' —— 内容和 X 一样，但 hash 不同（因为父变了、时间变了）。原 feature 分支完全不受影响。

cherry-pick = 搬 diff，不是搬 commit
08 · 高级用法
Advanced · 急救工具

高级二：Stash & Reset

写到一半要切分支？提交错了想反悔？这两个命令是救命稻草。

📥

git stash

暂存当前改动（不提交），让工作区变干净。切完分支再 pop 回来继续。

# 1. 临时收起改动
$ git stash
# 2. 切分支处理紧急 bug...
$ git checkout hotfix
# 3. 回来取出改动
$ git stash pop
像「抽屉」暂存 可多次 stash
↶

git reset

把 HEAD 指针移到指定位置，三种模式决定暂存区和工作区是否一起回退。

git reset --soft HEAD~1
只移 HEAD，改动留在暂存区
git reset --mixed HEAD~1
移 HEAD + 清暂存区（默认）
git reset --hard HEAD~1
⚠ 彻底回退，改动全丢
💡

急救锦囊：误删了 commit？git reflog 能看到所有 HEAD 移动记录，90% 的「误操作」都能救回来。

stash 抽屉，reset 时光倒流
09 · 高级用法
Advanced · 进阶利器

高级三：Submodule & Bisect

仓库套仓库、二分定位 Bug —— 大型项目的两把利器。

🧩

git submodule

在一个仓库里嵌套另一个仓库。常用于引入公共库、SDK、第三方组件。

# 添加子模块
$ git submodule add https://github.com/lib/lib.git

# 克隆含子模块的项目
$ git clone --recurse-submodules repo.git
仓库嵌套 独立版本
🔬

git bisect

二分查找定位 Bug 引入的 commit。只需标记「好」和「坏」，Git 自动缩范围。

# 开始二分
$ git bisect start
# 标记当前(坏)
$ git bisect bad
# 标记某个旧版本(好)
$ git bisect good v1.0
# Git 自动 checkout 中间版本测试
1000 commit → ≤10 步 自动定位
🎯

实战场景：线上突然报错但不知道哪次提交引入 —— git bisect 半分钟帮你找到「凶手」。

submodule 套娃，bisect 查凶
10 · 工作流对比
Workflow Comparison

三大工作流对比

不同团队规模，选不同的分支策略。选对工作流，协作效率翻倍。

Git Flow 大型项目

1main— 生产环境
2develop— 日常开发
3feature/*— 新功能
4release/*— 发布准备
5hotfix/*— 紧急修复

分支多、规范严，适合版本发布型产品

GitHub Flow 中小团队

1main— 唯一长期分支
2feature/*— 从 main 拉分支
3开发 + 提交
4发 Pull Request
5评审 → 合并 main

简单轻量，适合持续部署

Trunk-Based 高频发布

1main— 所有人直接提交
2短生命周期分支
3Feature Flag 控制功能
4快速合并、快速发布

主干开发，适合 DevOps 成熟团队

没有最好，只有最合适
