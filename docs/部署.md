# 云服务器部署指南

本文适用于当前项目的生产部署：Nginx 提供静态页面，FastAPI/Uvicorn 提供 `/api/*`，systemd 负责进程守护。示例基于 Ubuntu 22.04/24.04，站点目录为 `/opt/kaoyan-site`，域名请把 `example.com` 换成自己的域名。

> 本地开发继续使用 `python serve.py 8767`。生产环境不要直接暴露 `serve.py`，也不要把 Uvicorn 的 8000 端口开放到公网。

## 1. 部署结构与数据边界

```text
浏览器
  └─ HTTPS :443 → Nginx
       ├─ HTML/CSS/JS、/uploads/ → /opt/kaoyan-site
       └─ /api/* → Uvicorn 127.0.0.1:8000
                         ├─ 录取查询：SQLite 或 MySQL
                         └─ 内容后台：/var/lib/kaoyan/admission.db（SQLite）
```

仓库内的 `数据库/admission.db` 和 `uploads/content/` 只作为首次部署的种子数据。生产运行时把管理员、院校内容模块、真题模块、媒体记录和审计日志写到 `/var/lib/kaoyan/admission.db`，把封面和二维码写到 `/var/lib/kaoyan/uploads/content/`。这样 `git pull` 不会与线上数据冲突。即使把录取查询切换到 MySQL，这两处仍要单独持久化和备份。

后台会话保存在单个 Python 进程内，所以 Uvicorn 必须使用 `--workers 1`。如需多进程或多服务器，先把会话改为 Redis 等共享存储。

## 2. 服务器与域名准备

- 一台 Ubuntu 22.04/24.04 云服务器，建议至少 1 核 2 GB。
- 域名 A/AAAA 记录已指向服务器公网 IP。
- 安全组只对公网开放 `22`、`80`、`443`；不要开放 `8000`。
- 使用中国大陆服务器时，域名通常需要先完成 ICP 备案。

安装基础软件：

```bash
sudo apt update
sudo apt install -y git python3 python3-venv python3-pip nginx sqlite3 curl
```

创建低权限运行账户和目录：

```bash
sudo useradd --system --user-group --home /var/lib/kaoyan --create-home --shell /usr/sbin/nologin kaoyan
sudo chown kaoyan:www-data /var/lib/kaoyan
sudo chmod 0750 /var/lib/kaoyan
sudo install -d -o kaoyan -g www-data -m 0750 /var/lib/kaoyan/uploads/content /var/lib/kaoyan/raw
sudo install -d -o kaoyan -g www-data -m 0750 /opt/kaoyan-site
sudo install -d -o root -g root -m 0750 /etc/kaoyan
```

## 3. 从 GitHub 拉取代码

公开仓库：

```bash
sudo -u kaoyan git clone https://github.com/Remikacwz/Kongzhi-ZeXiao-website.git /opt/kaoyan-site
```

私有仓库建议给服务器配置只读 Deploy Key，再使用 SSH 地址：

```bash
sudo -u kaoyan git clone git@github.com:Remikacwz/Kongzhi-ZeXiao-website.git /opt/kaoyan-site
```

安装生产依赖：

```bash
sudo -u kaoyan python3 -m venv /opt/kaoyan-site/.venv
sudo -u kaoyan /opt/kaoyan-site/.venv/bin/pip install --upgrade pip
sudo -u kaoyan /opt/kaoyan-site/.venv/bin/pip install -r /opt/kaoyan-site/requirements-prod.txt
sudo chown -R kaoyan:www-data /opt/kaoyan-site

# 首次部署时复制种子数据；后续 git pull 不再覆盖 /var/lib/kaoyan
sudo install -o kaoyan -g www-data -m 0640 /opt/kaoyan-site/数据库/admission.db /var/lib/kaoyan/admission.db
sudo cp -a /opt/kaoyan-site/uploads/content/. /var/lib/kaoyan/uploads/content/
sudo chown -R kaoyan:www-data /var/lib/kaoyan/uploads
sudo find /var/lib/kaoyan/uploads -type d -exec chmod 0750 {} \;
sudo find /var/lib/kaoyan/uploads -type f -exec chmod 0640 {} \;
```

## 4. 配置生产环境变量

真实密码不要写入 Git 仓库或 systemd 单元文件。复制示例：

```bash
sudo cp /opt/kaoyan-site/deploy/kaoyan.env.example /etc/kaoyan/kaoyan.env
sudo chmod 0600 /etc/kaoyan/kaoyan.env
sudoedit /etc/kaoyan/kaoyan.env
```

生成两个不同的随机值：

```bash
python3 -c 'import secrets; print(secrets.token_urlsafe(36))'
python3 -c 'import secrets; print(secrets.token_urlsafe(36))'
```

至少修改以下配置：

```dotenv
KAOYAN_ADMIN_USER=你的后台用户名
KAOYAN_ADMIN_PASSWORD=第一个强随机值
KAOYAN_ADMIN_TOKEN=第二个强随机值
KAOYAN_COOKIE_SECURE=1
KAOYAN_SQLITE_PATH=/var/lib/kaoyan/admission.db
KAOYAN_UPLOAD_DIR=/var/lib/kaoyan/uploads/content
KAOYAN_RAW_DIR=/var/lib/kaoyan/raw
KAOYAN_DB_TYPE=sqlite
```

- `KAOYAN_ADMIN_USER` 与 `KAOYAN_ADMIN_PASSWORD` 必须同时设置；每次启动都会将 SQLite 中已有的默认管理员同步为这组凭据。
- `KAOYAN_ADMIN_TOKEN` 只用于高权限 Excel 导入接口，不能与登录密码相同。生产入口未设置它时，导入接口会返回 503。
- `KAOYAN_COOKIE_SECURE=1` 要与 HTTPS 一起使用。
- 三个路径变量把运行期数据放在 Git 仓库外；不要改回 `/opt/kaoyan-site`，否则版本更新容易与数据库冲突。

### 可选：录取查询使用 MySQL

单机部署优先使用 SQLite，最少出错。如果录取查询确需 MySQL，先初始化表和导入数据，再在环境文件中设置：

```dotenv
KAOYAN_DB_TYPE=mysql
KAOYAN_DB_HOST=127.0.0.1
KAOYAN_DB_PORT=3306
KAOYAN_DB_USER=kaoyan
KAOYAN_DB_PASSWORD=数据库强密码
KAOYAN_DB_NAME=kaoyan_admission
KAOYAN_DB_CHARSET=utf8mb4
```

环境变量优先于 `数据库/config.json`，因此无需把数据库密码提交进仓库。建表及导入：

```bash
mysql -u root -p < /opt/kaoyan-site/数据库/schema_mysql.sql
set -a
. /etc/kaoyan/kaoyan.env
set +a
/opt/kaoyan-site/.venv/bin/python /opt/kaoyan-site/数据库/import_admission.py --mysql
/opt/kaoyan-site/.venv/bin/python /opt/kaoyan-site/数据库/import_subjects.py --mysql
/opt/kaoyan-site/.venv/bin/python /opt/kaoyan-site/数据库/import_content.py --mysql
```

注意：MySQL 只承载录取查询等数据，内容管理仍依赖 `/var/lib/kaoyan/admission.db`。

## 5. 配置 systemd

```bash
sudo cp /opt/kaoyan-site/deploy/kaoyan.service.example /etc/systemd/system/kaoyan.service
sudo systemctl daemon-reload
sudo systemctl enable --now kaoyan
sudo systemctl status kaoyan --no-pager
```

检查本机 API：

```bash
curl --fail http://127.0.0.1:8000/api/health
```

预期返回包含 `"status":"ok"`。失败时查看日志：

```bash
sudo journalctl -u kaoyan -n 100 --no-pager
```

## 6. 配置 Nginx

复制示例并替换域名：

```bash
sudo cp /opt/kaoyan-site/deploy/nginx-kaoyan.conf.example /etc/nginx/sites-available/kaoyan
sudoedit /etc/nginx/sites-available/kaoyan
sudo ln -s /etc/nginx/sites-available/kaoyan /etc/nginx/sites-enabled/kaoyan
sudo nginx -t
sudo systemctl reload nginx
```

示例配置已完成以下保护：

- `/api/` 只代理到本机 Uvicorn。
- 允许页面访问 `/数据库/admin.html`，但拒绝下载 SQLite、`config.json`、原始 Excel、Python/SQL 源文件和 `.git`。
- 上传大小上限为 20 MB，满足 5 MB 图片和 Excel 导入。
- `/uploads/content/` 通过只读 alias 指向 `/var/lib/kaoyan/uploads/content/`，不能列目录或执行脚本。

先通过 HTTP 检查：

```bash
curl --fail http://example.com/api/health
curl --fail http://example.com/
```

## 7. 开启 HTTPS

```bash
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d example.com -d www.example.com
sudo certbot renew --dry-run
```

证书生效后验证：

```bash
curl --fail https://example.com/api/health
```

浏览器依次检查：

1. `https://example.com/` 首页正常。
2. `https://example.com/数据库/admin.html` 可用环境变量中的账号登录。
3. 新增一个草稿模块、上传封面、发布后在院校详情页显示。
4. `https://example.com/数据库/admission.db` 返回 403，而不是下载数据库。

## 8. 从 GitHub 更新版本

每次更新前先备份数据库和上传文件：

```bash
sudo install -d -o kaoyan -g kaoyan -m 0750 /var/backups/kaoyan
STAMP=$(date +%Y%m%d-%H%M%S)
sudo -u kaoyan sqlite3 /var/lib/kaoyan/admission.db ".backup '/var/backups/kaoyan/admission-$STAMP.db'"
sudo -u kaoyan tar -czf "/var/backups/kaoyan/uploads-$STAMP.tar.gz" -C /var/lib/kaoyan uploads
```

再执行无合并更新：

```bash
sudo -u kaoyan git -C /opt/kaoyan-site fetch origin main
sudo -u kaoyan git -C /opt/kaoyan-site pull --ff-only origin main
sudo -u kaoyan /opt/kaoyan-site/.venv/bin/pip install -r /opt/kaoyan-site/requirements-prod.txt
sudo systemctl restart kaoyan
curl --fail http://127.0.0.1:8000/api/health
sudo nginx -t
```

不要在服务器运行 `git reset --hard`。线上数据库和上传文件位于 `/var/lib/kaoyan`，不由 Git 更新，应通过备份迁移。

## 9. 自动备份与恢复

至少每日备份：

- `/var/lib/kaoyan/admission.db`
- `/var/lib/kaoyan/uploads/content/`
- 若启用 MySQL，再备份 `kaoyan_admission` 数据库
- `/etc/kaoyan/kaoyan.env` 应放入独立的加密密码库，不要混进公开备份

SQLite 正确备份方式是 `.backup`，不要在服务写入时直接 `cp`：

```bash
sqlite3 /var/lib/kaoyan/admission.db ".backup '/var/backups/kaoyan/admission-$(date +%F).db'"
```

MySQL 示例：

```bash
mysqldump --single-transaction -u kaoyan -p kaoyan_admission | gzip > "/var/backups/kaoyan/mysql-$(date +%F).sql.gz"
```

恢复 SQLite 前先停服务：

```bash
sudo systemctl stop kaoyan
sudo cp /var/backups/kaoyan/admission-YYYYMMDD-HHMMSS.db /var/lib/kaoyan/admission.db
sudo chown kaoyan:www-data /var/lib/kaoyan/admission.db
sudo chmod 0640 /var/lib/kaoyan/admission.db
sudo systemctl start kaoyan
```

## 10. 常见问题

| 现象 | 排查 |
|---|---|
| `502 Bad Gateway` | `systemctl status kaoyan`，再看 `journalctl -u kaoyan`；确认 127.0.0.1:8000 正常。 |
| 后台登录失败 | 检查环境文件中管理员用户名和密码是否同时设置，修改后重启服务。 |
| 登录成功但下一个请求又掉线 | 确认 Uvicorn 为 `--workers 1`，不要启动多个实例。 |
| HTTPS 下登录 Cookie 不生效 | 确认站点使用 HTTPS、`KAOYAN_COOKIE_SECURE=1`，并清理旧 Cookie。 |
| 图片上传成功但页面 404 | 检查 `/var/lib/kaoyan/uploads/content/` 文件是否存在、属主是否为 `kaoyan:www-data`，Nginx alias 是否一致。 |
| B 站封面抓取失败 | 云服务器需要可访问 B 站 API/CDN；失败时后台仍可手动上传封面。 |
| Excel 导入返回 503 | 未设置 `KAOYAN_ADMIN_TOKEN`，配置后重启服务。 |
| Excel 导入返回 401 | 请求未携带正确的 `X-Admin-Token`。 |
| `database is locked` | 检查是否重复启动了多个 API 实例或同时执行多个导入。 |
| 修改后页面没变化 | 强制刷新浏览器，并检查 Nginx 实际 `root` 是否为当前仓库目录。 |

## 11. 上线核对清单

- [ ] GitHub 仓库不含真实密码、Token、云数据库凭据。
- [ ] 服务器环境文件权限为 `0600`。
- [ ] Uvicorn 仅监听 `127.0.0.1:8000` 且只有 1 个 worker。
- [ ] 安全组只开放 22/80/443。
- [ ] HTTPS 已启用，后台 Cookie 使用 Secure。
- [ ] 数据库、配置文件、源码和 `.git` 无法通过网站下载。
- [ ] 后台登录、发布、图片上传和前台展示完成一次端到端验证。
- [ ] SQLite、uploads（以及可选 MySQL）已有定时备份，并演练过恢复。
